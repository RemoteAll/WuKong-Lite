### 发现并修掉的错误认知

1. **【真 bug】分区 `offset` 渲染与参考不一致，UBI 卷 offset 完全丢失**
   - 复核点：`wk image part`（C 头）与 `env` 分区前缀都走 `partition_table.appendItem`。
   - 参考口径：`gen_partition_table.py` / `mk_image.py` 都是 `"@{}".format(cfg["offset"])`，
     即**原样输出配置串**（`@0x4400`）；UBI 卷同样带 `@offset`。
   - 我们的实现：`@{X}` → 输出 `@4400`、`@100000`（少了 `0x`）；UBI 卷的 `offset` 被整段忽略。
   - 为什么之前没发现：验证夹具（`demo88-nor`、`envparts` 之外）**都不带显式 offset**，
     只有 devicetree 那类配置才用 `offset`。
   - 修法：`PartInfo` 增加 `offset_str`（保留原始串）、`appendItem` 与 3 处卷渲染改为原样输出；
     新增 `tools/checks/check_envparts.py`：spi-nor（带 offset）/ spi-nand+ubi（带卷 offset）/ mmc（GPT）
     三种媒体与 `mk_image.py -p` 对拍，**全部逐字节一致**（env.bin 4096 B）。
     修复前会分别差在 `@4400` vs `@0x4400`、以及 UBI 行缺 `@0x2800000`。

2. **【口径错误】文档里的命令/用例数量写错了**
   - 之前写「17 个顶层命令 / 31 条 image 子命令 / 57 条 CLI 用例」。
   - 实测（`main.zig` 分派去重 + 最新回归报告分段统计）：**14 个顶层命令**（build/config/defconfig/demo/fs/
     help/image/panic/rtt2freertos/run/sdk-update/shell/upg/version）、**`image` 29 个子命令**、
     **`upg` 7 个**、**`fs` 2 个**；CLI 用例 **53 条**（顶层 12 + image 29 + fs/upg 12）。

     并把「怎么数」写进文档，避免下次再凭印象填数。

3. **【静默错误输出】`itb` 条目带 `keydir` 时会产出「未签名」的 FIT**
   - 参考 `itb_create_image(its, itb, keydir, dtb, ...)` 会用 `keydir` 做 FIT 签名/图像加密。
   - 我们的 `itb` 处理器只读 `its`，忽略 `keydir` → 配了签名却生成未签名镜像，**且不报错**。
   - 修法：条目录里出现 `keydir` 直接报 `UnsupportedProc`（FIT 签名属 backlog P1-10，未实现），
     宁可失败也不假装成功。

## 2026-11-19 迁移推进（十二）：FIT 图像签名（P1-10 第一步）

- 用户原话：「请继续，另外再做一次全量审查纠正，避免又出现错的认知」。
- 承接上一轮审查结论（`itbimage` 支持 FIT 签名/加密），本轮先做**最容易验证且最常用**的一步：
  `images/*/signature-*` 的 RSASSA-PKCS1-v1.5(SHA-256) 签名。
- 实现（`src/tools/its.zig` + `src/tools/preproc.zig`）：
  - `postProcess` 不再拒绝 `signature*` 节点（`cipher*` 仍报 `SigningOrEncryptionNotSupported`）；
  - 新增 `its.signImages(parsed, allocator, io, keydir, timestamp)`：
    遍历 `images/*`，对含 `data` 且带 `signature-*` 子节点者，按 `algo`（只支持 `sha256,rsa*`）
    与 `key-name-hint` 从 `{keydir}/{hint}.key` 取私钥（PEM/DER 均可），
    对**原始 image data** 签名，写入 `value`、`signer-name = "mkimage"`、
    `signer-version = "1.0.0"`、`timestamp`（与参考 `_sign.py::sign_images` 同字段）；
  - `preproc` 的 `itb` 条目带 `keydir` 时先签名再 `buildFdtExternal`；`keydir` 解析用
    `datadir/keydir` 优先（目录也要能解析，不能复用只认文件的 `resolveIn`）。
  - `algo` 不是 sha256 或找不到私钥 → 明确报错（`UnsupportedAlgo` / `MissingFile`），不静默跳过。
- **对拍（`tools/checks/check_fitsign.py` + `tools/checks/fixtures/fitsign.json`）**：
  真实 RSA-2048 私钥（参考 SDK secure 方案的 `rsa_private_key.der` 复制成 `dev.key`），
  `mk_image.py -p` 与 `wk image preproc` 产出的 FIT：
  `signature-1/value` **逐字节相同**（`a2f00651…`），除 `timestamp` 外属性集合完全一致，
  `FAILS = 0`。
- 审查附带修正：`its.zig` 里原来那条「签名/加密节点明确拒绝」的单测改成
  「cipher 仍拒绝 + signature 允许且不填 value」；`cipher` 判定要用 `startsWith`
  （节点名是 `cipher-1` 而不是 `cipher`，用相等判定会漏）。
- **仍未实现（已登记 P1-10 剩余项）**：`sign_configurations`（对 FDT 区域做哈希签名，
  需要 `_fdt_regions.py` 的区域哈希）、`cipher` 图像加密（AES-CBC/CTR/ChaCha20）、
  公钥注入（`-K` 更新 dtb）。

  `tools/regression.ps1` **PASS=61 / FAIL=0 / SKIP=0**（6 个对拍脚本）。
