### Zig 0.17 API 要点（本机 zig 0.17.0）
- `main(init: std.process.Init)`；`init.io/gpa/arena/minimal.args`；argv 用 `std.process.Args.Iterator.initAllocator`（返回值指向内部缓冲，必须 dupe）。
- 文件：`std.Io.Dir.cwd()` + `dir.readFileAlloc(io, path, alloc, .unlimited)` / `dir.writeFile(io, .{...})` / `createDirPath`。
- 输出：`std.Io.File.stdout().writer(io, &buf)` → `&w.interface`；`std.Io.Writer.Allocating.init(alloc)` 用于字符串构建。
- `std.heap.DebugAllocator(.{}) = .init`（无 GeneralPurposeAllocator）；`std.ArrayList(T) = .empty`，`append(gpa, x)`、`toOwnedSlice(gpa)`、**无 `.writer()`**。
- `std.mem.find/findScalar/findAny`（旧 `indexOf*` 是别名）；`trimEnd`（无 trimRight）；`std.fs.path.resolveAlloc`（无 resolve）。
- `**` 数组/字符串重复被移除，用 `@splat` 或显式字面量。
- `Io.Mutex/Condition/Semaphore`：`lockUncancelable(io)` / `cond.waitUncancelable(io,&m)`；`Semaphore` 用 `.{}` 初始化；睡眠 `io.sleep(Duration.fromMilliseconds(n), .awake)`。
- 递归函数必须显式错误集（`anyerror!` 或具体错误集），否则 "dependency loop"。
- 标签是 `blk:` 不是 `blk:`（笔误易混）；`std.Io.Semaphore` 无 init。

### 格式对齐结论（已实测）
- **env**：`mkenvimage -s N` 是总大小；`-r` 只写一份 `crc(4)+flags(1)+data`；尾部 0xFF 填充；CRC 覆盖整个 data 区（含填充）。我们的实现在 `src/bsp/common/env_image.zig`，与参考 exe 输出 SHA256 一致。
- **分区表**：`wk image part --out/--json` 与 `gen_partition_table.py` 内容一致（参考在 Windows 用 CRLF）。FAL 行格式：`{FAL_PART_MAGIC_WORD, "name",FAL_USING_NOR_FLASH_DEV_NAME, off,size,0}, \`。
- **AIC 头**：V1 64B（magic 0x20434941，checksum=~sum32，load/entry u32）；AIC.FW 头 348B、META 512B/项、数据 2KiB 对齐。
- **页表**：AICP，20B 头 + 101×20B，头校验和写在偏移 36，整页 sum+1==0。

### 踩坑
- Kconfig `source` 递归解析时 ArrayList 扩容会让外层 `*Item` 失效 → 解析中必须存 **item 索引**。
- PowerShell 读写 UTF-8 文件务必 `Get-Content -Encoding UTF8` + `Set-Content -Encoding utf8`；否则中文注释被破坏（已踩，kconfig.zig 整文件重写）。
- `config set` 需保留原值类型（字符串带引号 / 数值不带），按旧值是否有引号判断。
- 设备用 `var dev: T = undefined; dev.init()` 时，字段默认值不会生效 → init 必须整体赋值 `self.dev = .{...}`（曾导致 `list_device` 枚举崩溃）。

### 第三阶段（提交 122ef3e）
- `src/tools/its.zig`：`.its` 解析 → FIT。Lexer 支持 `//`、`/* */`、`/dts-v1/;`、`&label`、`<0x.. 0x..>`、`(1 << 3)`、`[xx yy]`、`"str"`。
  Parser 递归函数统一 `anyerror`；子节点 `{` 由循环独占消费（不要重复 skip）。
  标签比较用 `std.meta.activeTag(a) == .xx`，不要直接 `==`。
- `postProcess`：遇到 `hash-N` 节点按 `algo`（crc32 大端 / md5 / sha1 / sha256）对 `data` 属性指向的同节点计算，
  **`value` 属性插到 `algo` 之前**（参考 mkimage 顺序）；`signature*` / `cipher` 直接报错（明确未实现）。
- `ensureTimestamp`：根 `timestamp` 属性置于首位（已存在时覆盖并移到首位）。
- 验证：同 timestamp 下 `wk image itb --its` 与 `mkimage -f` 用自写 `fdt_dump.py` 导出，
  `difflib` 对比 **logical same: True**（ref/ours_ref、app_ref/ours_app 两对）；字节数不同仅 libfdt 预留空间。
  注意：PowerShell 重定向的 dump 是 UTF-16LE，Python 读要 `encoding='utf-16'`。
- `src/tools/crypt.zig`：AES-128-CBC；Zig 0.17 路径是 **`std.crypto.core.aes.Aes128`**（`std.crypto.aes` 不存在）；
  `initEnc/initDec` + `ctx.encrypt(out_slice, in_slice)`。`--pad none|zero|pkcs7`。
  验证：与 `tools/scripts/openssl.exe enc -aes-128-cbc -K .. -iv .. -nopad` 加密/解密**双向逐字节一致**；
  `--pad zero` 与手工补零后 openssl 一致；NIST SP800-38A 向量入单测。
- 仍未做：RSA/SM2 签名（参考用 PyCryptodome PKCS1_v1_5）、AIC 头 sign/encrypt 区间联动、文件系统镜像工具。

### 第五阶段（提交 fd54178）FAT12/16 镜像
- `src/tools/fat.zig`：`Builder.addFile/addDir/addTreeFromDir` → `build()`。
  FAT12/16 自动选择（<4085 簇 FAT12，<65525 FAT16，否则 `Fat32Required`）；2 FAT、512 根目录项、media 0xF8；
  LFN（UTF-16LE + SFN 校验和，倒序 0x40 标志）、`~N` 短名去重、`.`/`..`、空目录、卷标。
- **AICF 信息块**（makefatfs.py::set_image_info_to_boot_sector）：偏移 0x80，magic "AICF"、
  `cksum=~sum32(40B)`、length=32、version=0x0101、image_size u64、used_size u64、dirent 两字段=0。
- 坑：引导扇区签名必须在 **0x1FE/0x1FF（510/511）**，不是 62/63；16 位总扇区够用时 32 位字段留 0（与 mformat 一致）。
- `serializeFat` 必须对 `i >= fat.len` 的簇补 0（未分配簇），否则越界 panic。
- 验证：参考 `mcopy.exe -i img -s ::/ outdir` 读回我们的镜像，文件名/目录/空目录/文件 SHA256 与源目录完全一致；
  `mformat` 无 mdir.exe（tools/scripts 只有 mcopy/mformat），校验只能靠 mcopy 回读 + Python 比对。

### 第六阶段（提交 caf73b7）RSA PKCS#1 v1.5
- `src/tools/rsa.zig`：PEM→base64→DER（最小 TLV 读取器）；私钥 PKCS#1/PKCS#8、公钥 SPKI/PKCS#1；
  `std.math.big.int.Managed` 模幂（平方-乘，`mul` + `divFloor(q,r,...)` 取余）+ EMSA-PKCS1-v1_5（SHA-256 DigestInfo）。
- **坑（重要）**：PKCS#8 的 PKCS#1 内层缓冲若用 `defer free`，返回的 `n/e/d` 就是悬垂指针（表现为签名全错、长度怪异）。
  密钥结构必须自己 `dupe` n/e/d 并在 `deinit` 释放。
- 验证：1 MiB 数据 + 2048 位密钥签名与 `openssl dgst -sha256 -sign` **逐字节相同**；
  openssl 能验我们的签名，我们也能验 openssl 的；篡改 1 字节退出码 1；签名 ~0.25s（含进程启动）。
- Zig 0.17：`std.crypto.core.aes.Aes128`；`std.base64.standard.Decoder.calcSizeForSlice/decode`；
  `fmtSliceHexLower` 已移除（自己写 hex）；`@splat` 必须能从赋值/参数推出类型。

### 第七阶段（提交 930d42c）sparse + cpio
- `src/tools/sparse.zig`：Android sparse。**规则经参考 img2simg.exe 实测**：
  连续全零块 → FILL(0)（不是 DONT_CARE），其余块 → RAW（**非零重复块不折叠**），
  尾部不足一块补零、total_blks 向上取整；头 28B / 块头 12B / magic 0xed26ff3a。
  验证：11 组边界样本 + 1 MiB FAT 镜像与 img2simg 输出**逐字节相同**。
- `src/tools/cpio.zig`：newc(070701)/crc(070702)；110B 大写十六进制头、名字与数据 4 字节对齐、
  TRAILER!!!、整档 512 对齐；crc 的 check = 数据字节和（mod 2^32）。
  **参考 cpio.exe（msys）的 ino/dev 取 NTFS 值、mode 为 666/777**，无法字节复刻；
  我们的 ino 顺序编号、dev/uid/gid=0、mode 644/755、mtime 由 `--mtime` 给（默认 0，可复现）。
  验证：参考 `cpio.exe -idm` 能解开我们的归档；与参考归档归一化头字段后结构完全一致。
- 坑：PowerShell 用 `.Replace('...','...\n...')` 写 Zig 源码会把 `\n` 变字面量 → 用编辑工具改多行。

### 第八阶段（提交 ac34525）FAT --auto + AICF 40B
- `autoTotalBytes()` 复刻 makefatfs.py -a：data = Σfiles(簇对齐) + Σdirs(1 簇)，按簇对齐；
  clusters<4085 → FAT12，否则 FAT16；fat = align((clusters+2)*bits/8, sector)；
  total = 1 sector + 2*fat + 512 根目录项(32 sectors) + data，按簇对齐、≥128 扇区。
  实测同一 rootfs（cluster=4, sector=512）与参考**同为 65536**，mcopy 回读内容一致。
- **AICF 终态是 fatupdate.exe 写的 40 字节**（不是 makefatfs.py 里的 32）：magic/cksum/
  len=40/version=0x0101/image_size/used_size/dirent_sect_id/dirent_data_len。
  参考的 dirent 列表是“已用扇区/目录扇区”数组（内容未完全逆向），我们写 0；
  used_size 我们用“元数据 + 实际分配簇”，与参考口径不同（README 已注明）。
- 参考 auto 镜像 mformat 根目录项是 112（小镜像默认），我们固定 512 →
  used_size 比参考大；不影响 FAT 有效性与读取。
- 坑：Zig 0.17 无 `**` 数组重复语法（单测里 `[_]u8{0} ** 5120` 会报错，用 alloc+@memset）；
  `utf16Len` 是 Builder 内嵌函数，顶层 helper 不能直接用。
- `zig build test --force` 不是 zig build 的参数（会被当编译器参数，退出码 1）。
