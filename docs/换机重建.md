# 换电脑：从零重建开发环境

> 目标：新机器上 clone 本仓库后，能用**一条命令**恢复出「能改 Zig 工具 → 能编固件 → 能烧板子」的完整环境。

## 一、三步走

```powershell
# 1) 仓库本身很小（约 5 MB），烧写工具、参考厂商工具都已随仓库提供
git clone https://chuanliuyun.com/git/szshlzxkjyxgs/WuKong-Lite.git
cd WuKong-Lite

# 2) 一键准备（检查工具 → 没有 SDK 时自动从 Gitee 官方镜像拉 → 解压工具链 → 编译并跑单测）
powershell -File tools\bootstrap.ps1
```

> **SDK 不再由我们的服 务端托管**（2.2 GB，且厂商 SDK 不应由我们分发副本）。
> `bootstrap.ps1` 默认从 **Gitee 官方镜像**浅拉：`https://gitee.com/artinchip/luban-lite.git`
> （实测 commit 与 GitHub 一致：`c6e3a477…`，国内速度快得多）。
> 已有本地 SDK 时用 `-SdkRoot <路径>` 直接复用，不会重复下载。

不确定缺什么时，先只做检查（不改动任何文件）：

```powershell
powershell -File tools\bootstrap.ps1 -Check
```

## 二、各项依赖从哪来

| 依赖 | 版本 | 来源 | 是否随本仓库提供 |
|------|------|------|-----------------|
| 参考 SDK `luban-lite` | commit `c6e3a4771a483fc4b42519b2882be3a21a50ef61` | **Gitee 官方镜像** `https://gitee.com/artinchip/luban-lite.git`（与 GitHub 同 commit） | ❌ `bootstrap.ps1` 自动浅拉（2.2 GB） |
| RISC-V 工具链 | Xuantie-900 gcc **14.1.1**（V3.2.0-20250627） | **SDK 内** `tools/toolchain/Xuantie-900-gcc-elf-newlib-mingw-V3.2.0-20250627-trim.tar.gz`（127 MB） | ❌ 需解压（`bootstrap.ps1` 自动做） |
| Zig | **0.17.x**（实测 0.17.1） | VS Code Zig 扩展自带，或 ziglang.org | ❌ |
| Python | 3.12 | python.org + `pip install kconfiglib` | ❌ |
| git | 任意较新版本 | — | ❌ |
| 烧写工具 `upgcmd` | 厂商 V1.4.2 | 本仓库 `tools/upgcmd/`（exe + 3 个 DLL） | ✅ |
| 参考厂商工具 | `firmware_security_encrypt` v1.0.1 / `mkuffs` | 本仓库 `tools/reference/` | ✅ |

> **最容易漏的一步**：SDK **不自带解压好的工具链**，只在 `tools/toolchain/` 放了压缩包。
> 忘了解压就会遇到 `RTT_EXEC_PATH` 找不到编译器。`bootstrap.ps1` 第 4 步专门处理这件事。

## 三、bootstrap.ps1 干了什么

1. 检查 `git` / `python`+`kconfiglib` / `zig`；
2. 检查 SDK 是否存在，并把它的 `HEAD` 与 `docs/official/UPSTREAM.json` 里记录的 commit 比对（不一致会警告，防止构建漂移）；
3. 把 SDK 复制到 `build\luban-lite`（排除 `.git` / `output` / `toolchain` / `doc`）；
4. 解压工具链到 `build\luban-lite\toolchain\`（默认取 `mingw` 的 **V3.2.0**，可用 `-TcPackage` 换）；
5. `zig build` + `zig build test`。

常用参数：

| 参数 | 作用 |
|------|------|
| `-Check` | 只体检，不改任何东西 |
| `-SdkRoot D:\sdk\luban-lite` | SDK 在别处（已有时直接复用） |
| `-SdkUrl <url>` | 换 SDK 源（默认 Gitee 镜像；也可指定 GitHub 或自备镜像） |
| `-SkipCopy` | 已手工准备好 `build\luban-lite`，只做工具链与编译 |
| `-SkipToolchain` | 工具链已就位 |
| `-SkipTest` | 跳过单测（不推荐） |
| `-TcPackage <path>` | 指定工具链压缩包（例如换 V2.6.1） |

## 四、环境就绪后的日常命令

```powershell
zig build test                                   # 139 项单测
powershell -File tools\regression.ps1            # 一键回归（PASS=74，19 个对拍脚本）
powershell -File tools\build-d12x-firmware.ps1   # 编 d12x 固件（全 Zig 打包）
powershell -File tools\make-flash-toolkit.ps1    # 生成可拷走的烧写工具包
```

烧写（板子需先进入升级模式：**PA0 接地**或按 UBOOT 键，然后上电/复位）：

```powershell
tools\upgcmd\upgcmd.exe -u COM25 -b 3000000 -p -v image "artifacts\firmware-d12x\xxx.img"
```

## 五、常见问题

**SDK clone 很慢**：默认从 **Gitee** 镜像拉（国内速度好得多）。若仍慢，可在快网络下 clone 一份，
用 U 盘/网盘拷到新机器，`bootstrap.ps1 -SdkRoot <路径>` 指向它即可，不会重复下载。
也可以用 `-SdkUrl` 换成你手边的任一镜像。

**`zig: command not found`**：VS Code 的 Zig 扩展会把 zig 放在
`%APPDATA%\Code\User\globalStorage\ziglang.vscode-zig\zig\x86_64-windows-0.17.x\zig.exe`，
把该目录加进 PATH，或从 ziglang.org 单独装。

**`kconfiglib` 缺失**：`pip install kconfiglib`（`rtt2freertos --verify` 与部分对拍脚本要用）。

**编译报 `can't link single-float modules with double-float modules`**：工具链版本与 `rtconfig.py`
的 `-march/-mabi` 不匹配。本仓库默认用 **V3.2.0**；若换 V2.6.1，需把 `build/luban-lite/toolchain`
换成对应包，并保证 `PRJ_TOOLCHAIN_VER` 与之相符。

**只想验证工具链是否可用**：

```powershell
build\luban-lite\toolchain\bin\riscv64-unknown-elf-gcc.exe --version
# 期望：Xuantie-900 elf newlib gcc Toolchain V3.2.0 ... 14.1.1
```
